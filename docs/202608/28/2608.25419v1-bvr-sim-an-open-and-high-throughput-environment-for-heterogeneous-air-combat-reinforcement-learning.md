## 摘要
超视距（BVR）空战是一个具有挑战性的强化学习领域，其特点是部分可观测性、长时域决策、能量管理以及有限武器。我们提出了BVR Sim，一个开源的Gymnasium风格环境，专为异构空战强化学习设计。BVR Sim支持多种JSBSim飞机模型，包括F-15、F-16、F/A-18和F-22，并具有可配置的武器、传感器、控制器和对手。统一战术动作接口指定期望的航向、高度、速度和武器发射，位于飞机特定的内环控制器之上，使策略能够跨异构平台运行。该环境提供可互换的Python和加速C++后端、面向实体的观测、组合奖励、脚本对手、回放与可视化，以及用于多智能体学习框架的适配器。在0.4秒决策间隔下，C++后端在1对1场景中实现每墙钟秒104个模拟秒，并在10对10场景中保持实用性。仅在F-16上训练的策略无需再训练即可迁移到四种未见过的飞机，通过飞机特定控制器自适应达到45.5%的平均胜率。MAPPO和HAPPO实验进一步验证了与标准多智能体强化学习流程的端到端兼容性。

## Abstract
Beyond-visual-range (BVR) air combat is a challenging reinforcement-learning domain characterized by partial observability, long-horizon decision making, energy management, and limited weapons. We present BVR Sim, an open-source Gymnasium-style environment designed for heterogeneous air-combat reinforcement learning. BVR Sim supports multiple JSBSim aircraft models, including the F-15, F-16, F/A-18, and F-22, with configurable weapons, sensors, controllers, and opponents. A unified tactical action interface specifies desired heading, altitude, speed, and weapon release above aircraft-specific inner-loop controllers, enabling policies to operate across heterogeneous platforms. The environment provides interchangeable Python and accelerated C++ backends, entity-oriented observations, compositional rewards, scripted opponents, replay and visualization, and adapters for multi-agent learning frameworks. At a 0.4-s decision interval, the C++ backend achieves 104 simulated seconds per wall-clock second in 1-vs-1 and remains practical through 10-vs-10 scenarios. A policy trained only on the F-16 transfers without retraining to four unseen aircraft, reaching a 45.5% mean win rate with aircraft-specific controller adaptation. MAPPO and HAPPO experiments further verify end-to-end compatibility with standard multi-agent reinforcement-learning pipelines.

## 2. 方法论

### 2.1 核心思想

- **分层动作抽象**：策略输出的是战术层指令（期望航向、高度、速度变化量及是否开火），底层由模型特定的飞行控制器（inner-loop controller）转化为具体舵面/油门控制。该设计使同一策略可跨不同动力学特性的飞机迁移。
- **异构单元级建模**：每个作战单元（飞机）拥有独立的配置——型号、动力学模型、控制器参数、挂载武器、雷达参数、初始状态及对手策略，而非按队伍统一硬编码。
- **双后端架构**：提供 Python 参考后端与 C++ 加速后端（经 pybind11 暴露），在“透明可调试”与“高吞吐”之间提供选择。

### 2.2 关键技术细节

- **动作空间**：
  - 默认战术动作为 `a_t = (k_ψ, k_h, k_v, k_f) ∈ MultiDiscrete(15, 15, 9, 2)`，分别对应航向（±45°）、高度（±80 m）、速度（±80 m/s）和二元开火决策。
- **观测空间**：
  - 实体导向（entity-oriented）的固定宽度表格观测：每个实体为 40 维行向量，涵盖自身、敌机、导弹等，维度为 `40 × N_e`。该结构保留对象边界与语义角色，便于后续使用注意力机制、掩码等模型。
- **奖励设计**：
  - 组合式奖励，涵盖闭合/跟踪几何、距离、高度优势与安全、导弹发射/重复发射惩罚、导弹结果、规避、速度、生存、战术优势及终局胜负等多项可配置权重项。
- **仿真多速率设计**：
  - 环境决策间隔为 0.4 s；C++ 后端内部以不高于 0.02 s 的子步长积分 JSBSim 动力学与导弹运动，兼顾战术频率与数值稳定性。
- **导弹模型**：
  - 通用导弹动力学涵盖燃烧期变质量、推力、重力、大气密度、马赫相关阻力与可用过载、指令速率限制，采用四阶 Runge–Kutta 积分。

## 3. 实验设计

论文主要开展四类实验：

   - 硬件：Windows 11，AMD Ryzen 9 5950X（16 核 32 线程），单进程 headless 运行。
   - 对比方法：Python 后端 vs. C++ 后端；每个规模 3 次重复，每次 500 个 transition（20 步 warm-up）。

2. **多智能体学习集成验证**

   - 算法：MAPPO（seed 1）与 HAPPO（seed 3），各约 2250 万环境步。
   - 目的：验证与标准 MARL 训练流程的端到端兼容性（非算法对比）。

3. **跨机型策略迁移实验**
   - 协议：1-vs-1 对抗固定规则对手；PPO-F16（仅在 F-16 上训练）和 PPO-All（在 F-16、F-15、F/A-18、F-22、F-4N 五种机型上训练）；冻结策略后评估 5 种机型，每个单元 960 集。
   - 消融对照：有无“机型特定控制器参数适配”（w/o adaptation 组使用默认 F-16 控制器参数）。

4. **导弹制导案例研究**
   - 匹配同一发射条件（16.21 NM 高偏置角发射），对比纯比例导引（PN）与多阶段复合制导律的命中时间与终端马赫数。

## 6. 主要结论与发现

1. **高吞吐优势**：C++ 后端在 1-vs-1 下达到 260.65 steps/s（约 104 倍实时），10-vs-10 仍在实时以上（约 22 倍实时）；速度相比 Python 后端提升 2.72×–6.55×。
2. **跨机型零样本迁移可行**：仅在 F-16 上训练的 PPO 策略，配合机型特定控制器适配，可迁移至四种未见飞机，平均胜率 45.5%（无适配仅 13.2%）；在全部五种机型上混合训练（PPO-All）进一步将平均胜率提升至 55.29%。
3. **机型特定控制器适配是迁移的关键**：F/A-18 上胜率从 1.88% 提升至 22.00%，F-22 上从 0.00% 提升至 80.11%，表明底层控制器参数的正确匹配对保持高层战术语义至关重要。
4. **标准 MARL 算法兼容**：MAPPO 与 HAPPO 均能在 BVR Sim 上完成约 2250 万步的持续学习并获得稳定的奖励提升，验证了与 CTDE 类算法的端到端兼容。
5. **异构配置能力已落地**：支持 F-15/F-16/F-22 混合 5-vs-5 场景的实例化，确认同一 episode 内多机型共存可用。

## 7. 优点

- **真正的异构支持**：不仅是不同策略作用于同一机型，而是从动力学模型、控制器参数、传感器、挂载到武器全面支持单元级差异化配置，这在现有公开环境中是独有的。
- **战术语义与底层控制的解耦**：统一的战术动作接口配合模型特定内环控制器，使得策略学习不必重新解决飞行稳定问题，显著降低了训练难度并支持跨机型迁移。
- **工程完整性突出**：包含 JSON 场景配置、实体观测、组合奖励、脚本对手、ACMI/Tacview 遥测导出、多种可视化路径（Web/OpenGL/DX11/UnrealCV）以及三个 MARL 框架适配器（HARL、MARLBenchmark、UHRL），做到了“开箱即用”。
- **可复现性强**：提供确切的 Git 标签（arxiv-v1）、SHA-256 清单、原始基准测量样本和脚本，附带文档化的调度方式。
- **高吞吐设计务实**：C++ 后端支持大规模并行训练，多速率子步进方案兼顾稳定性和效率。

## 8. 不足与局限

- **仿真保真度有限**：公开雷达/导弹参数被简化，电子战、通信、地形遮蔽、天气、详细对抗措施均未建模；飞机动力学受限于 JSBSim 自带模型精度。作者明确承认不用于作战级或认证级建模。
- **双后端不一致**：Python 与 C++ 后端不是逐位一致的数值实现，模型细节和浮点轨迹可能存在差异，跨后端对比结果需谨慎解释。
- **默认接口简化了目标分配**：目标选择和武器分配由模拟器内部逻辑处理，学习目标分配需要依赖保留的低层字段或扩展接口，当前版本不支持端到端学习武器-目标分配。
- **经验证据弱**：
  - MARL 验证仅单种子单运行，无冻结策略评估；
  - 跨机型迁移结果仅有聚合数据，无置信区间或逐 episode 记录；
  - 导弹制导对比仅单一案例，不具统计意义；
  - 论文无法支撑任何算法排名或性能 superiority 结论。
- **吞吐量数据方差大**：8-vs-8、10-vs-10 场景的 C++ 后端测量波动显著（如 10-vs-10 的 ±38.71 steps/s），影响基准的可重复比较。
- **缺乏社区验证**：环境由单团队开发，尚需第三方独立复现与压力测试；异构 5-vs-5 学习和显式协同分析仍属未来工作。
